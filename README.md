# Universal Modbus RTU Controller (STM32F103)

Программируемые логические контроллеры (ПЛК) являются основой промышленной автоматизации, однако они используют фиксированные промышленные протоколы связи, такие как Modbus. Это создает трудности при подключении к ПЛК нестандартной периферии, например, сервоприводов, магнитных датчиков или аналоговых устройств ввода-вывода. 

Из-за этого разработчикам встраиваемых систем приходится с нуля интегрировать набор устройств в каждый новый станок. Для решения этой проблемы был создан программный мост на базе микроконтроллера STM32F103C8T6, позволяющий разработчику собирать прошивку для микроконтроллера из нужных модульных компонентов.


## Ключевые архитектурные решения

### 1. Динамическая карта регистров (`RegisterTable`)
В классических прошивках адреса регистров Modbus жестко прописываются в коде. В данной архитектуре распределение адресов происходит **автоматически** на этапе регистрации каждого устройства.
* Каждое устройство-наследник в своем конструкторе вызывает методы добавления регистров (`addHoldingRegister`, `addInputRegister`, `addCoil`, `addDiscreteInput`), описывая свои параметры.
* Подсистема управления динамически выделяет адресное пространство под все четыре типа регистров Modbus, исключая ошибки ручной адресации.

### 2. Изоляция сбоев на уровне C++ (`UpdateGuard`)
В условиях реального производства зависание или сбой одного из периферийных устройств (например, по шине I2C или 1-Wire) может привести к краху всей системы. 
* В проект внедрен механизм защищенного выполнения `UpdateGuard`, использующий связку функций `setjmp` и `longjmp`. 
* Вызов метода `update()` каждого устройства обернут в контекст безопасности. При возникновении аппаратного сбоя управление аварийно возвращается в точку контроля, проблемный узел логируется и пропускается, а контроллер продолжает стабильно опрашивать остальные устройства.

### 3. Защита ресурсов микроконтроллера (`PinRegistry`)
Для предотвращения ошибок проектирования реализован строгий учет аппаратных выводов.
* Каждый драйвер устройства на этапе инициализации вызывает метод `claimPin()` для резервирования требуемых портов ввода-вывода.
* Если два устройства пытаются занять один и тот же пин, система фиксирует конфликт, заносит ошибку в лог и блокирует инициализацию некорректного узла.

### 4. Строгий ООП и полиморфизм (`BaseDevice`)
Архитектура избавляет разработчика от громоздких и монолитных конструкций `switch/case` или `#define`.
* Все периферийные модули наследуются от абстрактного базового класса `BaseDevice`, который определяет единый интерфейс с виртуальными методами `initialize()` и `update()`. 
* Главный менеджер управляет массивом указателей `BaseDevice *devices[]`, обеспечивая соблюдение принципа открытости-закрытости (OCP): добавление нового типа устройства не требует изменения кода ядра.

## Поддерживаемое оборудование

В репозитории реализованы классы-драйверы для широкого спектра периферии:
*   `Tc1508aDevice` — драйвер коллекторных моторов и сервоприводов.
*   `Pca9685Device` — 16-канальные ШИМ-контроллеры (интерфейс I2C).
*   `StepperMotorDevice` — шаговые двигатели.
*   `As5600Device` / `EncoderDevice` — магнитные энкодеры и инкрементальные энкодеры.
*   `Ds18b20Device` — цифровые датчики температуры (интерфейс 1-Wire).
*   `AnalogInput` / `AnalogOutput` — работа с АЦП и ШИМ-выходами микроконтроллера.
*   `DigitalInput` / `DigitalOutput` — дискретные линии ввода/вывода (GPIO) с поддержкой масок.

## Инструкция по добавлению новых устройств

Чтобы добавить собственное пользовательское устройство, создайте класс-наследник от `BaseDevice`:

```cpp
#pragma once
#include "BaseDevice.h"

class MyDevice : public BaseDevice
{
public:
    MyDevice(uint32_t pin) : _pin(pin)
    {
        setName("MyDevice");
        claimPin(pin);              // Зарезервировать пин
        addInputRegister("Value");  // Зарегистрировать регистры
        addHoldingRegister("Config");
    }

    void initialize() override
    {
        pinMode(getPin(_pin), INPUT_ANALOG);
        holdingRegisterWrite(0, 100); // Значение по умолчанию
    }

    void update() override
    {
        uint16_t config = holdingRegisterRead(0);
        uint16_t raw = analogRead(getPin(_pin));
        inputRegisterWrite(0, raw);
    }

private:
    uint32_t _pin;
};
```

### Важные правила разработки устройств:
* Вызывайте `claimPin()` и `addXxxRegister()` только в **конструкторе**.
* Используйте `getPin()` вместо прямого обращения к номеру пина — он проверяет владение.
* Если `getPin()` или операция с регистром завершается ошибкой, устройство помечается `_valid = false` и исключается из цикла обновлений.
* Индексы в методах `coilWrite`, `inputRegisterWrite` и т.д. являются локальными: `0` — первый регистр данного типа у конкретного устройства. Перевод локального индекса в глобальный Modbus-адрес происходит автоматически.
* Адреса назначаются в порядке регистрации: первый добавленный регистр получает адрес `0`, второй — `1` и т.д., независимо от того, какому устройству он принадлежит. Порядок определяется последовательностью вызова конструкторов в массиве `devices[]`.
* Ошибки накапливаются в статическом буфере, а порядок создания объектов в `devices[]` полностью определяет карту регистров.

```cpp
...

// Порядок создания объектов определяет карту регистров Modbus

    new MyLed(PC13),
    new AnalogInput(PA2),

```

## Сборка и прошивка

Проект разработан для среды **PlatformIO** в связке с фреймворком Arduino.

1. Откройте проект в VS Code с установленным расширением PlatformIO.
2. Подключите плату STM32F103C8T6 (Blue Pill) через программатор ST-Link.
3. Выполните сборку и загрузку прошивки (Upload).
